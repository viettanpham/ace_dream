# STARFRONT WORLD V2 — Character Asset Naming (8.2.3)

**Status:** Approved naming convention; asset generation ongoing. Not an implementation prompt.

## Directory and naming
- Physical source: `public/images/`
- URL from React: `/images/<classId>-<variant>.webp`
- `classId` is a stable lowercase key, independent of `classCharacterName` (lore) and `characterName` (Pilot Instance).
- Required per Character Class: `<classId>-fullbody.webp`, `<classId>-portrait.webp`.
- Optional additions: `<classId>-combat.webp`, `<classId>-casual.webp`, `<classId>-closeup.webp`.
- Shared background proposal: `character-hangar-bg.webp`; NOT created yet.

## Class IDs
`alviss`, `eric`, `marcus`, `victor`, `kaelen`, `lyra`, `selena`, `valentine`, `fortuna`, `aria`, `rhea`, `nova`.

## Compatibility / rollout
Existing eight pairs under `public/images/` are usable while V2-specific art is pending. The other four pairs must be supplied before rendering as enabled selectable options. Incomplete optional galleries must hide missing tiles or use a real available image, without broken network requests. Preview poster/crops are **not** substitutes for final full-body/portrait assets.

Manifest `FND8_CHARACTER_ASSET_MANIFEST_V2.json` is an export/planning reference. During FND-8 PLAN, AI Studio must audit FND-1 canonical registries and reuse their actual catalog/asset mechanisms rather than hardcode this sample into UI components. Media loading should use optimized WebP, lazy load optional/gallery art, responsive image sizing; no full background composite required.

### Asset handling
When a new official artwork is approved, export as `.webp`, keep the exact filename, add to `public/images/`, then update the canonical asset Definition/manifest and relevant MD. Preserve original art and avoid silent overwrites of existing files without confirmation.

## EXPANSION APPROVED — 2026-10-21
- Gallery is registry-driven, **no fixed maximum**. Add zero or more named variants per Class: `<classId>-uniform-001.webp`, `-outfit-001.webp`, `-pose-001.webp`, `-activity-001.webp`, `-event-001.webp`, `-art-001.webp` and increment `002`, etc. Core `-fullbody`, `-portrait` and optional `-combat`, `-casual`, `-closeup` remain valid.
- Story artwork is **optional**, 0–3 illustrations per chapter as a design guideline (not generated by default), e.g. `<classId>-story-001.webp`. Text-first storytelling. Story blocks (`text`, `image`, `quote`) reference registered assetIds; reuse an asset in Gallery/Story without duplicating files.
- Every registered asset has `assetId`, `classId`, `category`, `path`, optional `caption`, `sortOrder`, and actual availability validated before display. Additional photos do not require UI edits.
- Reuse the existing V1 gallery viewer where compatible: full screen, zoom/pan, gestures and desktop/mobile navigation after auditing actual code. Lazy-load gallery/story and maintain separate WebP thumbnail/full-size variants only if needed and declared.
- UI concepts Character Selection desktop/mobile, and Character Category desktop/mobile stay separate, all responsive. Do not confuse `classCharacterName` (Definition) with user `characterName` (Instance).
- This file + manifest are design contracts / export references. AI Studio audits FND-1 canonical catalogs and integrates without assuming this example JSON is a runtime registry.
